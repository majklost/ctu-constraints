# Artificial recipe workflow

`Recipe` is the central, portable description of one composed artificial
dataset. The same object is used to preview a sample, record how named artifacts
can be recreated, materialize them locally or on a cluster, and construct the
runtime dataset.

The canonical recipe files live in the tracked `recipes/artificial/` directory.
They do not belong below `data/`: generated data may be machine-specific, while
the recipe should travel with the code.

## Tune, resolve, and save

During tuning, artifact names may be omitted. Each unnamed item instead carries
a backup containing its complete generation configuration:

```python
recipe = Recipe(
    source="artificial/samples5000",
    layers=(
        SavedLayer(
            backup=power_layer_backup(
                (fake_ranges,) * 2,
                seed=53,
                target_class=ArteryClass.LUMEN,
                appearance=AppearanceKind.PLAQUE,
            ),
        ),
        SavedLayer(backup=power_layer_backup(real_ranges, seed=25)),
    ),
    deformation=SavedDeformation(backup=DeformationBackup(dc, seed=27)),
    rigid=SavedRigid(backup=RigidBackup(rc, seed=52)),
    noise=nc,
)

sample = preview_artificial_sample(recipe=recipe, sample_index=7)
```

Once the preview is satisfactory, assign stable names and save the expanded
recipe:

```python
cluster_recipe = recipe.with_names(
    layers={0: "fake-similar-offset-minus-3-v1", 1: "two-real-separated-v1"},
    deformation="default-deformation-v1",
    rigid="rotation-only-v1",
)
cluster_recipe.save_json(
    REPO_ROOT / "recipes/artificial/tworeal_fake_similar_offset_minus3.json"
)
```

Use a new artifact name when changing its backup. Names are identities shared by
recipes; reusing a name for different geometry is an error, not a versioning
mechanism. A complete worked example is in
`notebooks/ex5/fake_plaque.py`.

## Artifact references and backups

Every layer, deformation, and rigid entry has two independent fields:

- `name` identifies the stored artifact used by a resolved recipe.
- `backup` contains enough typed configuration to generate or verify it.

This permits both common forms: `{name, backup}` for a portable recipe, and
`{name, backup: null}` for an existing artifact that must never be generated by
that recipe. The dynamic notebook form uses `{name: null, backup}` and cannot be
saved as a usable dataset until `with_names()` resolves it.

`deformation: null` and `rigid: null` mean that the transformation is absent.
A rigid artifact in such a recipe is stored at source level, independently of
all deformation folders.

## Layer resolvers

Layer backups are generic calls into the registry in
`generators/layer_generators/registry.py`:

```python
LayerBackup(
    resolver="my-holed-layer-v1",
    params={"hole_count": 3, "radius_px": 5, "seed": 81},
)
```

A registered resolver returns either an arbitrary `LayerPatch` or a uniform
`MaskLayer`. The full form has independent per-pixel labels and grayscale:

```python
@register_layer_resolver("my-holed-layer-v1")
def resolve_holed(context, params):
    solid = make_solid_mask(context, params)
    holed = make_holes(solid, params)
    labels = np.full(solid.shape, -1, dtype=np.int8)
    labels[holed] = ArteryClass.PLAQUE
    image = np.full(solid.shape, np.nan, dtype=np.float32)
    image[solid] = make_gradient(solid, params)
    return LayerPatch(labels, image)
```

`labels == -1` and `image == NaN` are transparent. Their valid regions may be
different. For the common uniform case, return:

```python
return MaskLayer(mask, ArteryClass.LUMEN, AppearanceKind.PLAQUE)
```

Resolver names are stable recipe identifiers, not Python import paths. Give a
changed algorithm a new versioned name. Parameters must be finite JSON values.
`power_layer_backup()` is only a convenience constructor for the built-in
`power-v2` resolver; PowerPlaque types are not part of the Recipe contract.
Custom resolver modules must be imported before preview or ensure, ensuring
the CLI and notebook register the same functions before loading a recipe.
Resolvers must derive randomness from their JSON seed and `context.sample_index`;
the same call is used for preview and stored materialization.

For notebook-only iteration, call the resolver function directly and pass its
result through `normalize_layer_output()` into `preview_artificial_sample()`.
The same registered function is called by a backup during recipe preview and
materialization. Collections store `labels.npy` and `image.npy`.

## Materialize or validate

From the repository root, run:

```bash
.venv/bin/python scripts/ensure_recipe.py \
    recipes/artificial/tworeal_fake_similar_offset_minus3.json \
    --device cuda
```

The recipe's `source` is resolved relative to `get_data_folder()`, so the same
JSON works on different machines. The base source must already exist. For an
unusual layout, `--source-root /absolute/path` explicitly overrides it.

Before writing anything, `ensure()` checks the complete recipe:

- an existing artifact with the same typed backup is reused;
- a missing artifact with a backup is created;
- a missing artifact without a backup fails;
- a partial, invalid, unverifiable, or differently configured artifact fails.

This preflight prevents a late missing backup from leaving a partially created
recipe. Errors include field-level definition differences. Generation metadata
is written as incomplete first and marked complete only after the artifact is
finished.

`--overwrite` changes the final rule: conflicting artifacts that have backups
are replaced. This is intentionally explicit because another recipe may use the
same name. Prefer a new name for experiments; use overwrite only when replacing
the shared identity is deliberate. Replacing layer geometry also invalidates
derived SDF caches, and replacing a deformation recreates its dependent rigid
artifact.

The equivalent Python call is:

```python
report = cluster_recipe.ensure(device="cuda")
```

## SDF cache

SDF preparation is recipe-specific. Set `sdf_cache` on the recipe before saving
it; `ensure()` then creates or reuses the corresponding content-addressed cache:

```python
recipe = replace(
    recipe,
    sdf_cache=SDFCacheConfig(mode="scipy"),
)
```

The cache identity contains only geometry and SDF-relevant fields, so grayscale
noise and rigid motion do not produce unnecessary new
caches.

## Load for an experiment

Experiments load the checked-in JSON rather than duplicating its settings:

```python
recipe = Recipe.load_json(REPO_ROOT / "recipes/artificial/my_recipe.json")
source_root = recipe.resolve_source_root()
dataset = ComposedArtificialDataset.from_recipe(source_root, recipe)
```

Call the ensure script as a cluster setup step before constructing the dataset.
Dataset loading itself remains read-only and does not silently generate data.

The ex5 experiment exposes the recipe as a command-line argument:

```bash
.venv/bin/python experiments/ex5/initial_decoupled_new.py \
    --recipe recipes/artificial/tworeal_fake_similar_offset_minus3.json \
    --mode UNET \
    --modality deformed
```
